# AF-002：并发幂等预占与数据库提交之间存在短窗口

- 发现阶段：设计 100 并发相同 `Idempotency-Key` 的可靠性场景。
- 现象：首个线程已在 Redis 预占 key、但数据库事务尚未提交时，其他线程可能查不到 task，直接返回冲突。
- 根因：Redis 写入与 MySQL 提交不是同一事务，读取方把“暂时查不到”误判为异常。
- 修复：预占失败后在 3 秒上限内按 50 ms 轮询已提交记录；最终仍由数据库唯一索引保证只生成一条业务记录。
- 回归：`ConcurrentIdempotencyIntegrationTest` 同时释放 100 个请求，校验 100 个响应 taskId 相同、99 个标记为去重、`task` 与 `outbox_event` 均只有一条。
- 取舍：等待有明确上限，避免无限阻塞；若首次事务长期未完成，调用方收到可重试冲突而不是伪造成功。
